# Contributing to GARCH Volatility Forecasting Web App


Thank you for your interest in contributing! Your help is welcome and appreciated.  
This project aims to provide a robust, open-source platform for volatility modeling and forecasting using GARCH models, with a focus on usability, transparency, and reproducibility.

---

## How to Contribute

### 1. Fork the Repository

Click the "Fork" button at the top right of this page to create your own copy of the repository.

### 2. Clone Your Fork
```
git clone https://github.com/Aminah-Dodiya/Stock_Volatility_Dashboard.git
cd garch-volatility-dashboard
```

### 3. Create a New Branch

Name your branch according to the feature or bugfix you are working on:
```
git checkout -b feature/your-feature-name
```
or
```
git checkout -b fix/your-bugfix-name
```

### 4. Make Your Changes

- Follow the project’s code style and structure.
- Add or update tests as appropriate.
- Update documentation and docstrings where necessary.

### 5. Test Your Changes

- Ensure your code runs without errors.
- Run the FastAPI app and verify new features or bugfixes work as intended.
- If you add new dependencies, update `requirements.txt`.

### 6. Commit and Push
```
git add .
git commit -m "Add feature: brief description"
git push origin feature/your-feature-name
```

### 7. Create a Pull Request

- Go to your fork on GitHub.
- Click "Compare & pull request".
- Provide a clear title and description for your PR.
- Reference any related issues (e.g., `Closes #12`).

## What Can I Contribute?

- **Bugfixes:** If you find a bug, please open an issue first. PRs with bugfixes are welcome!
- **Features:** New model types, UI improvements, API endpoints, or analytics.
- **Documentation:** Improve the README, add usage examples, or clarify instructions.
- **Testing:** Add or improve tests, notebooks, or demo scripts.
- **Refactoring:** Simplify code, improve modularity, or enhance performance.

---

## Development Guidelines

- Use clear, descriptive commit messages.
- Write docstrings for new functions/classes.
- Keep pull requests focused and as small as practical.
- Use [PEP8](https://pep8.org/) style for Python code.
- UI/HTML: Favor accessibility and responsiveness.
- Add or update documentation as needed.

---

## Reporting Issues

If you find a bug or have a feature request:

1. Check if it’s already reported in [issues](https://github.com/Aminah-Dodiya/Stock_Volatility_Dashboard/issues).
2. If not, open a new issue with a clear title and detailed description.
3. Include steps to reproduce, screenshots, or code snippets if helpful.
